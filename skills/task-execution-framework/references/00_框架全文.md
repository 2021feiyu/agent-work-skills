# 中大型任务执行框架 v1.0

> **适用**：需要 30 分钟以上、跨多个章节 / 文件 / 系统，或涉及视觉、数据、发布的中大型任务。
> **不适用**：单点查询、一句话改写、简单命令。
> **目标**：把“靠临场发挥”变成“靠流程和证据”，让同样的任务在不同时间执行结果一致。
> **依据**：Anthropic《Building Effective Agents》《Effective Context Engineering》《Claude Agent SDK》；Harness Engineering；Double Diamond；Definition of Done。来源见文末。

**一句话**：先定义“做成什么样”，再找“别人怎么做”，再规划“我们怎么做”，最后才动手；做完**对照规划验收**，不对照感觉验收。

---

## 一、任务分级：不是所有任务都值得走全套

| 级别 | 判断 | 做法 |
|---|---|---|
| **S** | 30 分钟内、单文件、无歧义 | 直接做 + 交付前自检 |
| **M** | 半天到 2 天、多章节/多文件、有少量歧义 | 走完整 8 步，内部过 G0/G1 |
| **L** | 2—5 天、跨系统、视觉/数据/发布风险高 | 完整 8 步 + 用户在 G0/G1 确认 |
| **XL** | 5 天以上、多角色/多 Agent | 完整 8 步 + 编排者/子 Agent + 预算与检查点 |

**判断问句**：做错了，代价是“改几行”还是“整版重做”？后者至少是 L。

---

## 二、七条核心原则

1. **整体先于局部。** 先定结构、数据逻辑、视觉系统，再改单个卡片/段落。局部修改不得破坏整体一致性。
2. **参照先于设计。** 配色、版式、交互，先看 2—3 个外部优质参照，写清“借什么/不借什么”，再动手。
3. **规划先于执行。** 没有一页规划，不许开始写代码/改页面。
4. **证据先于结论。** “能跑/参数对/我觉得”不是证据；运行结果、截图、数据对账才是。
5. **单一事实来源。** 成品由源文件/脚本生成，不手改成品；文档是唯一事实来源，技能只做路由。
6. **变更分级。** 局部缺陷可以补；结构错位要回规划；前提错了必须停下来重写任务卡。**不要用局部补丁修前提错误。**
7. **上下文是预算。** 技能要薄，文档按需读；长任务用任务笔记/子 Agent 压缩上下文，不把整本手册塞进脑子。

## 三、八步主流程（核心）

> 第 0 步是前置分级，不计入八步；1—8 是八步本体。

| # | 步骤 | 核心问题 | 产出 | 闸门 |
|---|---|---|---|---|
| 0 | **受理与分级** | 这是 S/M/L/XL？做错的代价？ | 级别、是否需要用户确认 | — |
| 1 | **拆解与确认** | 目标、交付物、读者、载体、范围、验收、未知 | **任务卡** | **G0** |
| 2 | **澄清** | 哪些不清楚？哪些必须问？ | 澄清清单（已问 / 假设） | 用户确认 |
| 3 | **外部检索** | 别人怎么做？借什么、不借什么？ | **参照卡**（2—3 个） | — |
| 4 | **整体规划** | 结构/章节/数据/视觉/步骤/风险 | **一页规划 + 验收矩阵** | **G1** |
| 5 | **细节设计** | 每个模块怎么落地？ | 执行清单、组件/数据/交互规格 | — |
| 6 | **执行** | 按规划做，不边做边改方向 | 可运行/可看的产物 | — |
| 7 | **对照校验** | 规划项都在吗？整体一致吗？ | 验收矩阵结果 + 问题清单 | **G2** |
| 8 | **调优与交付** | 补丁、重规划还是重做？ | 最终版 + 变更记录 + 交付说明 | **G2 通过** |

### 0 受理与分级

- 先把语音/口语任务改写成**结构化一句话**：给谁、做什么、交付什么、什么时候要。
- 判断级别；L/XL 先不要动手，先做任务卡。
- 识别“高风险动作”：发布、覆盖、删除、对外发送——必须单独确认。

### 1 拆解与确认（任务卡）

任务卡是**合同**：它定义“做成什么样”，也是最后验收的依据。

| 字段 | 写什么 |
|---|---|
| 目标 | 一句话，动词开头，可判断完成 |
| 交付物 | 文件/链接/决策/数据，具体到路径或形式 |
| 读者与载体 | 谁读、在哪读、读多久、桌面/手机/打印、读完做什么 |
| 范围 | 做什么 / **明确不做什么** |
| 约束 | 时间、工具、数据、风格、权限 |
| 验收标准 | 3—5 条，可验证（不是“好看/好用”） |
| 未知与风险 | Top 3；哪些要问，哪些先假设 |
| 级别 | S/M/L/XL |

**判据**：任务卡写完，你能用一句话回答“什么叫做完了”。

### 2 澄清

- 只问**会改变方案**的问题，最多 3—5 个；不要用提问逃避判断。
- 用户不在场时，把假设写进任务卡/规划，标注“待确认”，不要暗猜。
- 语音转文字的任务，先复述成结构化要点，确认无误再往下。

### 3 外部检索

三条线，每条 1—3 个高质量参照即可：

| 线 | 找什么 | 例子 |
|---|---|---|
| 事实/领域 | 数据、政策、行业现状 | 官方统计、规划纲要、招聘报告 |
| 设计/UX | 同类页面怎么做、配色/版式/交互 | Stripe Press、读库、The Pudding、同行业优秀站点 |
| 执行/Agent | 任务怎么拆、怎么验、怎么迭代 | Anthropic 五种 workflow、Harness、DoD |

**参照卡**（每个参照一行）：

| 参照 | 看到的 | 借什么 | 不借什么 |
|---|---|---|---|
| URL/名称 | 一句话描述 | 1—2 条可迁移原则 | 明确不抄的部分 |

规则：

- **看真实页面/截图，不只看文字描述。** 视觉判断必须看整张图。
- 不复制，提取原则；至少写一条“为什么不适合我们”。
- 没有参照就开始设计，视为流程违规。

### 4 整体规划（一页规划）

一页纸，八块，缺一块不算规划：

1. **方向**：一句话结论/主张。
2. **结构**：章节/模块/页面顺序，每块的目的。
3. **数据逻辑**：来源、口径、时间、单位、计算方式。
4. **视觉/交互系统**：参照、底色、结构色、强调色、字体、版式、组件、交互点。
5. **执行步骤**：里程碑，每步的产出。
6. **风险与对策**：Top 3。
7. **验收矩阵**：任务卡的验收标准 → 证据 → 方法。
8. **明确不做**：防止范围膨胀。

**G1**：L/XL 任务在动手前把一页规划给用户确认；M 任务至少自己过一遍，能指出“整体长什么样”。

### 5 细节设计

- 把规划拆到**可执行单元**：组件、数据表、交互状态、边界情况、文件结构。
- 视觉任务：先定设计令牌和组件规格，但**最终判断靠截图**。
- 代码任务：先定接口、数据结构、测试方式。
- 判据：每个规划项都有对应的执行单元；没有“到时候再说”。

### 6 执行

- **先骨架后血肉**：先做端到端骨架（能打开、能跑通），再填内容，最后做视觉/交互打磨。
- 一次只动一个层级：结构 → 内容 → 视觉 → 交互；不要一边改结构一边抠颜色。
- 单一事实来源：改源文件/分片，重新构建；不手改成品。
- 记录变更：改什么、为什么、影响哪些验收项。
- 长任务：维护 `task_notes.md`（决策、来源、未决问题），防止上下文丢失。

### 7 对照校验（两轴四类）

**两轴**：

- **完整性**：规划里的每一项，产物里都有吗？
- **一致性**：整体风格/结构/数据口径，前后一致吗？有没有“局部正确、整体冲突”？

**四类检查**：

| 类别 | 检查 | 证据 |
|---|---|---|
| 内容/数据 | 来源、日期、单位、口径、计算 | 对账表/抽样 |
| 视觉 | 整页节奏、配色、字号、留白、卡片 | 整页截图 + 关键区块原尺寸 |
| 交互 | 每个按钮/表单/状态 | 真机点一遍 |
| 工程 | 构建、console、溢出、性能 | 构建日志/Playwright |

**独立复核**：换一种方法/视角；可以让子 Agent 扮演“挑刺的评审”，只给任务卡和产物，不给你的解释。

### 8 调优与交付

先分类问题，再决定动作：

| 问题类型 | 判断 | 动作 |
|---|---|---|
| **L1 局部缺陷** | 不影响结构/系统/验收标准 | 直接补，记录 |
| **L2 结构错位** | 章节/布局/数据流/视觉系统不一致 | **回到第 4 步**，改规划，再执行 |
| **L3 前提错误** | 读者/载体/目标/约束变了 | **停下来**，重写任务卡，重新确认 |

**红线**：不要用一堆 L1 补丁去修一个 L3 问题。越补越乱。

交付说明必须包含：产物在哪、怎么用、验收结果、已知限制、来源、下一步。

## 四、三个核心工件（可直接复制）

### 4.1 任务卡

```text
目标（一句话）：
交付物（路径/链接/形式）：
读者与载体（谁/在哪/读多久/桌面或手机/读完做什么）：
范围（做 / 明确不做）：
约束（时间/工具/数据/风格/权限）：
验收标准（3—5 条，可验证）：
未知与风险（Top 3）：
任务级别（S/M/L/XL）：
```

### 4.2 一页规划

```text
1 方向：
2 结构（章节/模块/顺序/目的）：
3 数据逻辑（来源/口径/时间/单位/计算）：
4 视觉/交互系统（参照/色/字/版式/组件/交互点）：
5 执行步骤（里程碑/产出）：
6 风险与对策（Top 3）：
7 验收矩阵（验收标准 → 证据 → 方法）：
8 明确不做：
```

### 4.3 验收矩阵

| 规划项 | 验收证据 | 方法 | 结果 |
|---|---|---|---|
| 例：全年日历 12 个月 | 1月—12月可见、每月 3 个动作 | 截图 + DOM 检查 | 通过/不通过 |
| 例：桌面正文可读 | 正文 ≥17px、行宽 820—900 | 截图 + 计算样式 | 通过/不通过 |
| 例：数据口径一致 | 1,270 万 / 18.9% 全文一致 | 全文检索 + 抽样 | 通过/不通过 |

## 五、变更控制：防止“单点修改，整体崩坏”

| 级别 | 触发 | 是否回规划 | 是否重新验收 |
|---|---|---|---|
| L1 局部 | 错别字、单个卡片内容溢出、单个颜色微调 | 否 | 局部 + 整页快照 |
| L2 结构 | 章节顺序、版式系统、数据口径、交互流程 | **是** | 全量 |
| L3 前提 | 读者、载体、目标、范围、发布方式 | **是，重写任务卡** | 全量 + 用户确认 |

**自检**：这次改动，是在修 L1，还是在给 L3 打补丁？

## 六、上下文与工具纪律（Harness）

- **任务契约**：任务卡 + 验收标准 = 完成谓词；不要用“我觉得可以了”当完成。
- **验证循环**：执行 → 检查 → 反馈 → 修正；每一轮都要有证据。
- **上下文预算**：技能薄、文档按需读；长任务写 `task_notes.md`；研究/校验可拆子 Agent，只回摘要。
- **工具边界**：发布、覆盖、删除、对外发送，必须单独确认；不要静默产生副作用。
- **状态持久化**：源文件、版本历史、变更记录、验收矩阵，放在工作空间里，不靠记忆。
- **完成谓词**：流畅的总结不是成功证据；截图、运行结果、对账、线上复验才是。

## 七、反例：2026-10 求职手册（我自己的执行审计）

| 八步 | 当时做了什么 | 遗漏 | 后果 |
|---|---|---|---|
| 0 分级 | 当成一次普通改版 | 没判断这是 L 级、涉及视觉系统 | 反复返工 |
| 1 拆解 | 直接打开文件改 | 没写任务卡；把“指导网站”当成手机 H5 | 方向错，字号/版心全错 |
| 2 澄清 | 没问载体、读者、基准 | 没确认“桌面优先”“以 V2 为基线” | 后面全部错位 |
| 3 外部检索 | 凭感觉配色 | 没看 Stripe Press/读库/The Pudding | 黄纸+深蓝/黑，温度冲突 |
| 4 整体规划 | 没有一页规划 | 边改边想，单点改 CSS | 局部正确、整体反差 |
| 5 细节设计 | 直接写分片 | 没有组件/数据/验收矩阵 | 遗漏交互、数据口径 |
| 6 执行 | 执行很快 | 没冻结方案，反复推翻 | V3 整体废弃 |
| 7 对照校验 | 只查参数/局部截图 | 没对照规划做整页一致性检查 | 没发现“中段节奏平/标题黑红对半” |
| 8 交付 | 过早交付 | 没有验收矩阵和限制说明 | 用户连续否决 |

**三条教训**：

1. **先定载体和基线，再谈设计。** 能在手机打开 ≠ 应该在手机读；已发布版本是基线，不是可以随手推翻的草稿。
2. **先看参照，再做配色。** 底色与结构色必须同温；不要为一个错误前提（黄纸）不断加补丁。
3. **单点修改必须过整体检查。** 改一个卡片/颜色后，必须看整页联系表和关键区块，确认没有制造新的反差。

## 八、交付前 12 项（通用）

- [ ] 任务卡里的验收标准全部满足
- [ ] 一页规划里的每一项都在产物里
- [ ] 整页/整系统一致性检查过（不是只看局部）
- [ ] 数据来源、日期、单位、口径一致
- [ ] 交互逐项点过（含空态/错误态）
- [ ] 构建通过、console 无错、无横向溢出
- [ ] 目标载体上真机/真浏览器看过（桌面/手机/打印）
- [ ] 视觉：整页联系表 + 关键区块原尺寸截图
- [ ] 独立复核（换方法/换视角/子 Agent）
- [ ] 版本、历史、变更记录齐全
- [ ] 相关说明文档/空间说明已同步
- [ ] 发布/覆盖/删除等外部动作已获确认，线上复验
