# 长文档 → 可视化页：内容完整性核验

> **适用**：把指导手册、白皮书、培训材料、制度文件等**长文档**改写成 H5 页面时（非数据看板默认场景）。
> **层级**：P0 决策正确性——内容在改写中丢失，等于让人读到一个不完整的版本，且**页面看起来完全正常**。
> **来源**：本地《H5开发手册》§10 三层比对法，实战数据来自一次 217 项抽查。

---

## 0. 为什么需要单独一套方法

数据看板的正确性判据是"数字能否重算"；长文档改写的正确性是"**内容有没有在结构化过程中丢**"。
后者更隐蔽：表格被压成卡片、四列并成三列、范围文本变成图上一个点——**页面不缺任何一块，但信息已经少了**。

**不要用人眼核。** 人眼在 200 项以上的内容面前只能抽查，而缺失恰恰发生在没抽查到的地方。

---

## 1. 三层比对法

### 第一层 · 标题结构比对

提取源文档全部 `#`~`####` 标题，逐一在 HTML 中搜核心词。

- 命中即 OK；**MISS 大多是格式差异误报**（HTML 改写标题 / 去空格 / 换说法），逐个甄别后再判缺失。
- 典型改写：`1.3 关键里程碑节点` → `1.3关键里程碑节点`；`模块3：专项深度拆解` → `MODULE 03 · ART PIPELINE`。
- 这一层只能发现"整章丢失"，发现不了"章内被压缩"。

### 第二层 · 表头比对（**诊断价值最高**）

提取源文档表格（`|` 开头行，下一行是 `|--|` 分隔行即为表头），取**首列表头**在 HTML 中搜索。

| 现象 | 说明 |
|---|---|
| 表头 MISS | 整表缺失 |
| 表头命中但列数减少 | 表列被合并省略，**内容无声丢失** |

**实战**：97 个表头中 11 个 MISS —— 「四级签认表 ×6」被压成一句话、「数据出处详表」「折算方式」列被压成卡片，均为实质缺口。

**表格改图表时**：数据进了图里不算缺失，但**范围文本写法会丢**（如「30,000–60,000」只出现在图数据的 60000），必须在图 caption 里补回范围。

### 第三层 · 数据点抽查 + 归一化

手工列出关键数字 / 术语清单，**先归一化再比对**：

```python
import re, unicodedata

def norm(s):
    s = unicodedata.normalize('NFKC', s)      # 全角 → 半角
    s = re.sub(r'\s+', '', s)                 # 去所有空格
    return (s.replace('×', 'x').replace('·', '')
             .replace('（', '(').replace('）', ')'))

miss = [p for p in points if norm(p) not in norm(html)]
```

> **归一化是必须步骤。** 实战数据：217 项直接比对报 **42 项 MISS**，归一化后只剩 **6 项真缺失**（4 项写法差异、2 项需补文本）。
> 不做归一化，会把大量时间花在核误报上，最后因为疲劳而漏掉真问题。

---

## 2. 三条实现纪律（顺序不能错）

### 2.1 先剥 `<script>`，再剥标签，最后归一化

```python
html  = re.sub(r'<script>[\s\S]*?</script>', '', html)   # ① 先剥脚本块
plain = re.sub(r'<[^>]+>', '', html)                     # ② 再剥标签
result = norm(plain)                                      # ③ 最后归一化
```

- **不剥 `<script>`**：内嵌 ECharts 库里的 SVG path（如 `M13.5,26.9V0`）会命中「V3」等版本号，造成整片误报。
- **不剥标签**：`<span class="num-hl">1-14</span> 个工作日` 这类被标签隔断的数字会全部误报（归一化后变成 `1-14</span>个工作日`）。

### 2.2 残留扫描必须先排除内嵌库

扫 `FIXME`、旧版本号这类残留时，**先剥离 `<script>` 块再扫**。理由同上——库内符号会命中关键词。

### 2.3 含反引号 / 复杂字符的正则不要用 `bash -c "python -c '...'"` 内联传参

shell 会吃掉或折叠转义，导致**替换静默失效**。写成 `.py` 脚本文件再执行。

---

## 3. 空缺标记盘点

扫描源文档中「待填 / 待确认 / 待校准」，定位需填充项。
**填充值必须符合业务实操逻辑并标注口径**（例：「标准件基线 ≥20 件/月，单件产值约 ¥1,500」），不要留成看起来像真数据的占位符。

---

## 4. 删除类修改的连带检查（四项，缺一项就会留下断口）

删除对标数据、参考段落、整块图表之后，必须同步检查：

| # | 检查项 | 实战案例 |
|---|---|---|
| 1 | **图表轴 max / 项数** | 删掉 10.9 后，投产比图 `max` 需从 11.5 调到 5；y 轴类别数同步 |
| 2 | **句子衔接** | 删 callout 整段后句尾是否通顺（「对标三七：…」整段删、metric 卡「｜三七对标 X」删后句尾要干净） |
| 3 | **数据出处表** | 删行后是否过空，需要合并或补替代来源 |
| 4 | **零残留复检** | 全局 `grep 关键词` 复查，确认没有半句话残留 |
