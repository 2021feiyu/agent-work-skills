# Executive H5 视觉系统

用于高管汇报、经营驾驶舱与培训型可视化页。目标不是制造统一的“模板脸”，而是用同一套角色令牌和层级方法，做出不同但完整的视觉方向。  
可复制参数以 `assets/executive-h5-kit/tokens.css` 为准；本文解释如何选择与验收，避免两处各维护一份色值。

## 1. 设计方向卡：写代码前完成

| 字段              | 要回答的内容                 | 不合格写法             |
| --------------- | ---------------------- | ----------------- |
| Purpose         | 谁，在什么场景，做什么判断          | “做一个高端看板”         |
| Tone            | 选择一个主方向与密度             | “科技、简约、奢华、活泼都有一点” |
| Constraints     | 投屏/桌面/手机、离线、打印、浏览器、数据量 | 写完再补移动端           |
| Differentiation | 观众离开后能复述的一个记忆点         | “蓝紫渐变和玻璃卡片”       |
| Motion          | 静态 / 克制 / 演示，以及一个主动效时刻 | “所有卡片和图都动”        |
| Accessibility   | 对比、键盘、减少动效、文字等价物       | 交付前再补 ARIA        |

推荐输出句式：  
“这是给领导层投屏的 8 分钟经营简报；采用瓷白社论风，以主数字和异常证据的 7/5 非对称构图为记忆点；默认克制动效，数据更新保留短过渡，移动与打印可读。”

## 2. 四套主题不是四种滤镜

### 2.1 Porcelain / 瓷白高管

- 气质：冷静、精确、现代，但不落入 SaaS 蓝紫渐变模板。
- 适用：经营汇报、跨部门演示、需要兼顾投屏与打印。
- 构图：冷灰底、白表面；深色 Hero 仅作为可选的单一高对比区，使用低饱和蓝青，默认也可用浅色 Hero；主证据大面积留白，铜青只用于当前项或关键动作。
- 材质：细边与近距阴影为主，不强制玻璃。
- 避免：每张卡都蓝色顶条、所有主数字都渐变、浅灰弱文。

### 2.2 Editorial / 纸本铜金

- 气质：商业出版物、克制、可信，适合战略、规划与模型选型。
- 适用：结论和文字较多，需要来源、注释与方法说明的决策报告。
- 构图：暖白纸面、墨蓝标题、铜色强调、细规则线；允许社论式大标题和双栏；若使用深色 Hero，采用暖石墨而非冷蓝灰。
- 材质：1px 规则线比重阴影更合适；圆角小于瓷白主题。
- 避免：把“纸本”做成泛黄低对比，或把铜金同时当普通类别色与风险色。

### 2.3 Midnight / 墨夜指挥

- 气质：专注、沉浸、指挥室，但不是游戏霓虹。
- 适用：投屏、运营监控、现场演示和暗色环境。
- 构图：近黑蓝底，略亮表面，关键数据用高明度青色；大面积暗色留白。
- 材质：细亮边、局部光晕只给 Hero；正文和次要文字仍保持高对比。
- 避免：纯黑底、荧光色满屏、无限扫描线、每卡发光、暗灰小字。

### 2.4 Corporate / 企业蓝

- 气质：稳健、正式、品牌一致。
- 适用：有明确企业品牌色、跨项目需要统一识别。
- 构图：浅冷灰底、白卡、深蓝导航与主图，青绿只作辅助；深色 Hero 使用低饱和海军蓝，不以纯黑代替。
- 材质：克制边框与阴影，强调对齐和可读性。
- 避免：企业蓝铺满所有图表系列，导致当期、参照、风险和类别无法区分。

## 3. 深浅表面与边缘系统

### 3.1 本次自检发现的问题

V3 的深色 Hero 暴露了三个设计缺口，不能只当作“颜色偏好不同”处理：

1. 浅色页面的三套主题都默认使用深色大卡，把本应是少数“高对比时刻”的深色表面变成了默认模板。
2. 纸本的暖浅底搭配冷蓝灰深卡，色温关系没有先审；深色虽然能抓注意力，却会与页面材质脱节。
3. 深色卡只写 `border-color:transparent` 和通用阴影，没有同色系边缘、过渡色与柔光；浅底浅卡的内容突出方法也不够完整。

V4 因此把顺序固定为：**必要性审查 → 深色与底色关系 → 边缘过渡 → 浅底浅卡替代方案**。

### 3.2 先判断：这块深色真的必要吗

浅色页面默认使用同主题浅色表面。深色大卡是可选择的强调手段，不是“高管感”的默认配置。

| 场景                             | 建议                                  |
| ------------------------------ | ----------------------------------- |
| 开场或总览只有一个核心判断，需要唯一视觉锚点         | 可以评估一个深色 Hero                       |
| 投屏演示、内容短、周围留白充足、后续图表颜色较多       | 可以少量使用，但必须控制面积与边缘                   |
| 长文阅读、培训讲义、密集表格、连续多页            | 默认浅色 Hero，避免反复出现深色块                 |
| 一页已有多张深色卡或多个高饱和视觉              | 不再增加深色大卡                            |
| 主要诉求只是让普通卡片与页面分开               | 使用 surface / border / spacing，不动用深色 |
| 打印、复印、投影环境不可控，或深色中的图表与资产无法同步适配 | 默认浅色，除非有实测证据                        |

把“一屏一个高对比时刻”作为设计起点。若深色区域超过首屏约三分之一，只触发一次必要性复审，不把面积比例当成机械合格线。  
Carbon 将浅色 UI 中的局部深色区域称为 inline theme / high contrast moment；普通层级仍由同主题 layering tokens 完成。这正是“少量深色可用、普通卡片不滥用”的依据。

### 3.3 再选深色：与浅底建立色彩关系

深色不是简单取 `#000`，也不是把品牌色任意压暗。默认从页面底色或品牌色的色相家族出发，降低明度、控制饱和度，并保持文字与图形的可读性。

| 浅底环境      | 优先深色方向                  | 默认避免              |
| --------- | ----------------------- | ----------------- |
| 冷灰、瓷白、企业蓝 | 低饱和蓝青、石板蓝、深海军蓝          | 纯黑、高饱和电蓝、与品牌无关的紫黑 |
| 暖白、纸本、米金  | 暖石墨、深 taupe、深棕灰、低饱和橄榄灰  | 冷蓝灰直接压在暖纸底上       |
| 中性浅灰      | 从品牌色族中选择深色，并保持全页一致      | 每张卡各选一个深色         |
| 深色页面      | 比页面略亮的同主题表面，不套用“浅底深卡”规则 | 在暗底上继续压暗到失去层次     |

“同温”不是禁止一切冷暖对比，而是要求对比有明确品牌或叙事依据。没有依据时，默认同色族、低饱和、同温最稳定。  
深色 Hero 的内部渐变只允许同色系的小明度变化，不能变成另一块抢眼的多色渐变背景。

### 3.4 选中之后：边缘做三层，不做硬切边

深色与浅底交界处需要同时处理三种关系：

1. **内部**：同色系轻微明度过渡，避免一块平而死板的深色。
2. **边缘**：约 1px 的渐变过渡边，让深色的受光侧与接近浅底的一侧有所区别。
3. **外部**：同色低透明柔光 + 极轻内高光，减少硬切边；投影只辅助分离，不形成厚重黑壳。

`tokens.css` 使用双层背景实现边缘，不使用 mask，也不占用业务卡片的 pseudo element：

```css
.hero {
  background-color: var(--h5-surface-hero); /* 回退色 */
  background-image:
    linear-gradient(145deg, var(--h5-hero-start), var(--h5-hero-end)),
    linear-gradient(135deg, var(--h5-hero-edge-start), var(--h5-hero-edge-end));
  background-origin: padding-box, border-box;
  background-clip: padding-box, border-box;
  border: 1px solid transparent;
  box-shadow:
    inset 0 1px 0 var(--h5-hero-highlight),
    0 16px 34px -22px var(--h5-hero-shadow),
    0 0 24px var(--h5-hero-halo);
}
```

技术依据：`background-clip` 可分别控制多层背景的绘制区域；透明边框让 border-box 层只在边缘显露。`box-shadow` 的 blur、spread 与 inset 可组成外部柔光和内部高光。  
这些参数是主题起点，不是所有项目通用值。透明叠色和投屏效果仍需在真实成品中复核。

避免：

- 只加深一整块黑色投影，制造“贴纸浮起”的厚重感。
- 用高饱和霓虹外发光代替过渡，导致深色块更突兀。
- 四边使用同一条高亮描边，或再做 mask 渐变环盖住内容。
- 深色卡变了，卡内文字、图标、图表、图片却仍沿用浅底版本。

### 3.4.1 备选边缘处理：羽化（柔化边缘）

上一节的三层硬边是一种做法，不是唯一做法。当深色或彩色大卡压在浅底上、交界处仍显"像贴上去的一块"时，**羽化边缘**是另一条可试的路子 —— 相当于 PPT 的「柔化边缘」，让卡片的透明度在边缘一圈内渐变到 0，直接融进背景。

它解决的是**明度差本身**，不是靠加边框或加阴影去"过渡"。判断依据很直接：把边缘放大数倍看，如果交界是一条锐利的分界，硬边方案还没做完；如果边缘能看出 5–15px 的渐变带，冲突感会明显下降。

```css
/* 四边 alpha 渐隐；只改透明度，不模糊内容 */
.card--soft {
  --soft: 5px;                 /* 起始值，见下方"半径怎么定" */
  -webkit-mask-image:
    linear-gradient(to right,  transparent 0, #000 var(--soft), #000 calc(100% - var(--soft)), transparent 100%),
    linear-gradient(to bottom, transparent 0, #000 var(--soft), #000 calc(100% - var(--soft)), transparent 100%);
  -webkit-mask-composite: source-in;
  mask-image:
    linear-gradient(to right,  transparent 0, #000 var(--soft), #000 calc(100% - var(--soft)), transparent 100%),
    linear-gradient(to bottom, transparent 0, #000 var(--soft), #000 calc(100% - var(--soft)), transparent 100%);
  mask-composite: intersect;
  box-shadow: none;            /* 羽化与投影互斥，见下 */
}
@media print {
  .card--soft { -webkit-mask-image: none; mask-image: none; border: 1px solid #C9D6E0; }
}
```

**三条硬约束，违反会静默出错：**

1. **`mask` 会连 `box-shadow` 一起裁掉** —— 羽化与投影是替代关系，不能叠加。用了羽化，就没有外投影，卡片分量改由「内部同色阶渐变 + 边缘渐隐」承担。
2. **打印必须关羽化** —— 打印链路没有 alpha 混合，羽化区域会渲染成一圈灰边。打印时恢复硬边与细边框。
3. **羽化会让"可视边界"内缩** —— 内容到边的视觉距离变短，padding 需相应加 2–4px 补回。

**半径怎么定（不写死）：**

没有通用值，按两件事实测：卡片短边尺寸、与背景的明度差。经验区间是 5–16px —— 200px 高的卡配 5px 只去掉"刀切感"，配 12–16px 才看得出"融进去"。明度差越大，需要的羽化越宽；浅色卡压在浅底上本来就柔，通常不需要。

直接看放大 **4–8 倍**的边缘截图判决，不要看整页缩略图（在 1600px 画布上 5px 与 8px 的差别肉眼几乎不可分）。

**什么情况不该用：**

- 卡片本身就是浅色、与背景明度接近 —— 羽化后彻底没有边界，位置感消失；
- 一屏内卡片密集 —— 每张都羽化会糊成一片，反而看不出分区；
- 信息分区必须明确（如报表分区、可点击区域）—— 边界是功能，不是装饰；
- 以打印/归档为主的材料 —— 纸质上羽化无意义，还要多写一条打印降级。

**外部依据**：PowerPoint「柔化边缘」是对图片/形状应用高斯模糊蒙版，本质即边缘 alpha 羽化；CSS 侧对应 `mask-image` 的多重渐变与 `mask-composite`，MDN `mask-composite` / `mask-image` 有机制说明，具体参数仍需回到成品截图裁决。

### 3.5 浅底浅卡：不用深色，也要有重点

浅色页面的大多数内容应通过同主题层级突出，而不是靠反色。按以下顺序分配注意力：

1. **位置与跨度**：主证据放首屏主轴，给更大栅格跨度和留白。
2. **字号与字重**：结论、主值和辅助信息拉开，不靠全页彩色字。
3. **表面色调**：`bg → surface-1 → surface-2` 同温分层；重要区可用轻微浅色调，不依赖阴影。
4. **边缘与阴影**：普通卡用细边和少量近距影；只有覆盖、悬浮或边界不足时才加强阴影。
5. **小面积强调**：品牌色、状态色只给当前项、关键数字或行动，不把整卡染成品牌色。

可使用 `.h5-card--hero-light`：浅表面之间的轻微色差负责分区，内容尺寸与位置负责聚焦。  
普通卡片边界没有统一的 3:1 合格线；但交互控件、关键图形和必要边界仍需满足相应的非文本对比要求。不要为了“柔和”把文字、口径和来源一起淡化。

浅底浅卡的三类常见失败：

- 背景与卡片几乎同色，又没有间距、细边或分区，信息黏成一片。
- 为了把卡片分开而给每张卡加深阴影，所有内容都像浮在最上层。
- 内容本身没有主从，只靠浅色顶条、浅蓝底和大面积品牌色补“重点”。

### 3.6 深浅表面复审清单

1. 这块深色承担什么唯一的叙事职责？改成浅色后是否真的会损失焦点？
2. 深色与页面底色是否同温或有明确对比依据？深色是否低饱和而非纯黑？
3. 当前页是否只有这一个高对比区域？深色面积是否挤压了真正的数据证据？
4. 边缘是否有深色侧、浅底侧和外部柔光的自然过渡，而非硬切边或厚黑影？
5. 深色卡内的文字、图标、图表、图片是否按局部深色主题重新适配？
6. 如果改用浅底浅卡，能否用位置、尺寸、留白和表面层级得到同样清晰的焦点？

外部方法来源：Carbon Color / inline themes 与 layering；Material 3 Elevation 的 tonal surfaces 与按需阴影；Atlassian Color 的 emphasis levels 与 inverse tokens。详见主文档 §12。

## 4. 令牌架构

### 4.1 角色优先于色值

组件只引用角色，不引用 `--blue-600` 之类的具体色阶：

```css
.surface { background: var(--surface-1); color: var(--text-1); }
.kpi-value { color: var(--data-current); }
.compare { color: var(--data-reference); }
.risk { color: var(--status-negative); }
```

主题只覆盖角色值。市场涨跌与经营正负分别使用 `--market-rise/fall` 和 `--status-positive/negative`，不要互相猜含义。

### 4.2 表面层级

至少四种表面：

| 令牌                                                 | 用途                        |
| -------------------------------------------------- | ------------------------- |
| `surface-0`                                        | 页面底色                      |
| `surface-1`                                        | 普通内容表面                    |
| `surface-2`                                        | 分区、选中、次要浮起                |
| `surface-hero`                                     | 深色高对比主视觉，需通过必要性、色彩关系与边缘审查 |
| `hero-light`                                       | 浅色页面的默认强调表面，以浅色调差而非反色建立重点 |
| `hero-start/end`、`hero-edge-start/end`、`hero-halo` | 深色 Hero 的内部层次、渐变边缘与外部柔光   |

浮层另有 `surface-overlay`，避免抽屉与普通卡完全处于同一层级。  
表面层级的第一工具是明度与留白，边框和阴影只是补充。

### 4.3 字阶与间距

采用角色字阶，不在组件里随机写 13、15、17、19、22：

- Display：页面结论或 Hero，桌面约 40–64px，移动通过 `clamp()` 收缩。
- KPI：主值约 44–72px，次级 KPI 28–40px。
- Title：卡片/章节 18–24px。
- Body：桌面正文约 15–17px；培训长文可更大。
- Meta：约 12–13px，但不能通过低对比变成不可读。

间距使用 4/8 基础节奏。页面级留白大于组件内留白；主从关系也应体现在间距，而不仅是分割线。

## 5. 构图模板

### 5.1 Executive Hero：7 / 5 主证据构图

```text
┌──────────────────────────────────────────────────┐
│ Eyebrow / 期间                    演示进度 / 操作 │
│ 结论式大标题（最多两行）                          │
├───────────────────────┬──────────────────────────┤
│ 主 KPI + 一句判断     │ 本期风险 / 行动摘要       │
│ 主趋势或主对比（7列） │ 异常排序或贡献（5列）     │
├───────────────────────┴──────────────────────────┤
│ 次要证据 / 口径 / 来源                            │
└──────────────────────────────────────────────────┘
```

适合高管首页。主数字与主图可以组合，但不要同时争抢第一焦点。  
侧栏放“异常与行动”通常比再放三张同构 KPI 卡更有决策价值。

### 5.2 Evidence Trio：主图 + 两个异构证据

主图占 6–8 列，两个辅助证据采用不同形式，例如一张偏差排序和一张文字结论带。  
避免三个完全相同的 donut/gauge，因为它们通常只重复“占比”，无法解释变化原因。

### 5.3 Editorial Decision：结论 + 证据 + 方法

适合战略与研究报告：上部大结论，中部双栏证据，下部方法与来源。  
来源属于内容，不要用几乎不可见的 10px 浅灰隐藏。

### 5.4 Operational Exception：状态带 + 例外优先

顶部只显示整体状态和当前筛选；主体优先列出需要处理的异常，趋势和明细退居第二层。  
运营页不需要为了“高管感”强行放超大 KPI 和社论标题。

## 6. KPI 与结论带

### 6.1 主 KPI 的六个区域

1. 指标标签：明确业务对象。
2. 主值与单位：单位视觉上附属但不可省略。
3. 对比：vs 预算/同期/上期，写明基准。
4. 变化：数值 + 方向 + 语义，不只给红绿箭头。
5. 期间：数据截至或当前筛选期间。
6. 可选趋势：只在形状能提供额外信息时出现。

主值不要用无法读取的渐变文字。打印恢复纯色；数字滚动时读屏直接获得最终值。

### 6.2 决策摘要带

一条高质量摘要带通常回答四件事：本期判断、主要变化、最大风险、建议动作。  
它比“欢迎来到驾驶舱”或重复页面标题更有价值。最多突出一个风险和一个动作，不把整段分析报告塞进去。

## 7. 数据色与图表质感

### 7.1 三类色板不可互换

- Categorical：区分离散类别，不暗示大小。
- Sequential：表达单向数值大小，深浅/明暗有秩序。
- Diverging：表达围绕业务中点的偏差，中点清晰。

状态色只用于状态。普通分类序列不应把红、绿、黄自动分配给第一、第二、第三类。

### 7.2 一个主图的默认配色

- 当期/选中：品牌或数据强调色。
- 同期/预算/参照：中性灰或低饱和线型。
- 异常：状态色 + 文字/图标/形状，不只靠颜色。
- 其他类别：中性色阶；只有类别本身是重点时才用多色分类板。

### 7.3 质感优先级

先保证数据映射、排序、标注和留白，再加材质。  
柱体圆角、线条平滑、面积渐变都属于主题微调，不应成为所有图的固定“高级配方”。  
柱宽按绘图区与类别数计算，不能把某项目的 34/26/19px 当成所有屏幕的标准。

## 8. 状态与细节

每个交互组件按适用性检查：

- Default：信息清楚，边界和层级足够。
- Hover：提供反馈但不改变布局，不引发内容跳动。
- Pressed：短促、明确，不使用大幅缩放。
- Focus-visible：2px 左右可见焦点圈与偏移，不能只在鼠标 hover 时出现。
- Selected：颜色之外再有标记、字重或位置。
- Disabled：不能操作且原因可理解；不与普通弱文混淆。
- Loading：只有真实等待时显示；本地快速加载不闪骨架。
- Empty：说明是没有数据、筛选无结果还是期间无数据，并提供下一步。
- Error：保留旧数据或可读摘要，给出重试/定位，不让 `clear()` 后空白。

## 9. 反模板化验收

| 问题                   | 通过信号                    |
| -------------------- | ----------------------- |
| 换掉 Logo 后是否像任意 AI 模板 | 至少有一个与业务叙事相关的构图或证据形态    |
| 是否所有信息都像同样重要         | L1/L2/L3 一眼可辨，主证据占比明显   |
| 是否靠颜色制造层次            | 黑白截图仍能看出大小、位置和留白层级      |
| 是否靠动画制造高级            | 暂停动画后页面仍完整、精致、可讲述       |
| 是否弱文过弱               | 来源、口径、单位、标签在实际底色上可读     |
| 是否有风格拼贴              | 圆角、边框、阴影、字体、图标与动效属于同一方向 |
| 是否移动只是缩小             | 内容重排、图表重配、导航变抽屉，文字仍可读   |

## 10. 设计交付说明模板

交付时只需写清六项，不附上一篇抽象设计理论：

1. 体验模式与受众。
2. 主题方向与选择理由。
3. 一个记忆点。
4. 字体、色彩与密度令牌来源。
5. 动效等级与 reduced-motion 行为。
6. 已验收视口、页签、交互状态和打印结果。
