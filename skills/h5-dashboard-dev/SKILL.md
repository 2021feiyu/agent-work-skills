# H5 数据看板与可视化汇报

把看板做成“能帮助决策、适合现场讲述、可以稳定交付”的产品，而不是图表和卡片的集合。
本入口只负责路由、关键门禁和资源定位；详细方法放在主文档与 references，可复制代码放在 assets。

直接复用本技能已验证蓝图、只替换品牌令牌和数据时，不重复做形式化检索。

## 2. 五阶段工作流

1. **定位**：明确受众、使用场景、载体与汇报方式；区分高管简报、运营监控、分析探索、长文培训。
2. **叙事**：写“问题 → 结论 → 证据 → 行动”映射；每页只承担一个主问题，标题尽量直接表达结论。
3. **定调**：选择体验模式、主题、字体、密度、一个记忆点和动效等级；先产出设计方向与令牌，再写页面。
4. **实现**：以 PageRegistry、指标元数据和设计令牌为单一事实来源；组件统一注入样式；成品只由源码构建。
5. **验收**：同时过数据、交互、视觉、响应式、可访问性与交付一致性；视觉结论必须来自当前成品的真实截图。打印/PDF只在需求明确时验收，正式复杂打印优先转 Word。

## 3. 不可绕过的门禁

1. **决策正确性**：数据期间、单位、空值、来源和口径必须可追溯；不同口径不得靠星号注释混入同一排行榜。
2. **单一事实来源**：导航来自 PageRegistry，计数与跨视图指标来自同一数据，筛选只有一处状态，成品不手改。
3. **内容始终可读**：无 JS、动画被中断、切页或打印时，核心内容仍可访问；不得以隐藏内容作为入场前提。
4. **完整减少动效**：同时覆盖 CSS、ECharts 首次与更新动画、数字滚动、无限动画和 JS 平滑滚动，并响应偏好变化。
5. **交互可操作**：页签具备方向键与 ARIA 关联；抽屉具备焦点进入、Escape、焦点返回和状态同步；焦点清晰可见。
6. **动效解释变化**：数据更新优先 `setOption` 过渡，页面切换默认不清空图表重播；最新输入优先，旧动画不得覆盖新状态。
7. **视觉必须实看**：当前成品在桌面、移动端及关键交互状态下截图并目视；截图清单绑定成品哈希。真实打印/PDF不作为默认验收，只有明确交付需求时才检查对应产物。
8. **交付面一致**：工作版、所有“最新/交付物/分发”副本与快照的版本、数据期间和哈希一致；发现漂移先停止交付。

图表零基线、单位精度、字体字号、圆角阴影等完整规则见主文档。不要把某个历史项目的玻璃、渐变或尺寸参数当成普遍审美标准。

## 4. 高管演示的质量底线

- 5 秒能看出本期判断，30 秒能理解核心证据，3 分钟能沿导航讲完一条决策故事。
- 每页一个视觉锚点；卡片至少有主、次、辅助三级，不做“等大同质卡片海”。
- 浅色页面默认用同温浅色表面建立层级；深色大卡须审必要性、色彩关系和边缘过渡，浅底浅卡不得只依赖阴影。
- 每页最多一个主动记忆点；惊艳来自构图、数字、叙事和反馈的配合，不来自所有元素同时运动。
- 默认静态即可阅读；演示动效是增强层。提供减少动效与直接定位路径，不强迫观众看完动画。
- 至少检查默认、悬停、选中、焦点、空、错误、加载与禁用中适用的状态。

## 5. 交付前回答

1. 这一页让谁做什么判断？最重要的结论是否由标题和视觉层级共同表达？
2. 关键数是否能独立重算？跨图、跨卡、跨表是否一致？
3. 只用键盘能否完成切页、筛选和关闭窗格？减少动效后是否仍完整可用？
4. 动态图表是否帮助理解“什么变了”，还是只在重复播放？
5. 当前截图是否对应当前哈希？所有对外副本是否真的是同一版？

## 6. 维护规则

- 保持本入口精简；新方法写入主文档或对应 reference，可复用代码进入 assets。
- 规则必须标注层级：决策正确性、可用性门禁、质量建议、主题默认值；不得把主题偏好升格为铁律。
- 自动审计报警先抽样复核，再批量修文件；校验脚本只证明其覆盖范围，不替代浏览器与视觉验收。
- 结构性重构前备份到 `versions/`；保留旧版，不以追加补丁代替定期重构。
