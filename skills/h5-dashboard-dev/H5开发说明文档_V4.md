# H5 数据看板与可视化汇报开发说明 · V4

> V3 完成结构性升级：不再按“历次踩坑顺序”组织经验，而按实际设计与交付顺序组织。
> V4 针对深浅表面做二次设计修正：浅色页面的深色大卡必须先审必要性与色彩关系，再处理渐变边缘和柔光；同时补齐浅底浅卡的内容层级。
> 核心目标：让高管演示具备明确叙事、辨识度、可用的动态交互和稳定的离线交付，同时保留数据正确性与工程可追溯性。

## 0. 规则分级与阅读路径

### 0.1 四级规则，避免把偏好写成铁律

| 层级 | 判断依据 | 例子 | 违反后的处理 |
|---|---|---|---|
| P0 决策正确性 | 会不会让人误读、误判或拿到错误版本 | 空值当 0、跨口径排名、数据日期取墙钟、交付副本漂移 | 必须修复，停止交付 |
| P1 可用性门禁 | 用户能否在目标载体中读取、操作、使用键盘或减少动效 | 无 JS 内容消失、页签不能键盘操作、移动图表被挤没 | 必须修复 |
| P2 设计质量 | 是否清晰、有层级、有辨识度、动效是否有意义 | 卡片海、标题只有主题没有结论、所有图都重播 | 按本手册质量门槛验收 |
| P3 主题默认值 | 某一视觉方向的起始参数 | 圆角、阴影、玻璃、背景渐变、具体色值 | 可调整，以最终效果与对比度为准 |

旧版中“不要用 1px border”“永远不要整页渐变”“切页必须重播”等表述均降为 P3 或可选模式。
真正的判据是：信息是否清楚、对比是否足够、风格是否统一、交互是否帮助理解。

### 0.3 一条总判据

先问“这个改动会不会让人得出相反结论”，再问“它是否让人更快、更有信心地做出判断”。
前者是正确性，后者是设计质量。圆角 12 还是 20 通常不是缺陷；首屏没有结论、所有信息同等醒目，则是设计缺陷。

## 1. 端到端工作流

### 1.1 阶段 A：定位与约束

在写代码前形成一段可执行的体验定义：

- 受众：领导层、部门负责人、分析师、培训学员，不能一页同时满足所有人。
- 场景：投屏讲述、现场培训、桌面自查、手机扫码、离线转发、打印归档。
- 载体：H5 是技术形态，不等于手机单栏。桌面汇报与移动兜底可以共存。
- 汇报方式：主讲人引导、观众自由探索，或两者兼有。
- 技术约束：离线单文件、浏览器/WebView 基线、数据量、是否需要打印与无障碍。

产出：一句话体验定义，例如“供领导层投屏的 8 分钟经营简报，桌面优先、390px 可读、默认克制动效、可切换到自由分析”。

### 1.2 阶段 B：叙事与信息架构

先写四列，不先画图：

| 业务问题 | 结论标题 | 证据视觉 | 下一步行动 |
|---|---|---|---|
| 本期经营是否健康 | 增长仍在，但成本增速已连续两期高于收入 | 主 KPI + 收入/成本趋势 | 查看成本异常主体 |
| 异常集中在哪里 | 两家主体贡献了大部分偏差 | 排序条形 + 偏差贡献 | 进入主体明细 |

每页只回答一个主问题。页面标题优先写结论，主题名可放在 eyebrow 或导航中。
“运营效能”是主题；“人均产出改善，但一线梯队仍未恢复”才是汇报标题。

### 1.3 阶段 C：设计方向与方案对比

至少明确以下六项：

1. 体验模式：Executive Brief / Operational / Analytical / Learning。
2. 视觉方向：瓷白社论、纸本铜金、墨夜指挥、企业蓝等，只选一个主方向。
3. 字体角色：展示字、正文字、数字字；离线环境不依赖远程字体才能显示层级。
4. 色彩角色：表面、文字、品牌、数据、状态，禁止组件随意写色值。
5. 一个记忆点：主数字构图、结论带、图表形态或导航进度，只选一个主动记忆点。
6. 动效等级：静态、克制、演示；不是“有/无动画”的二选一。

采用新技术或新交互时，先做“候选方案 × 优缺点 × 本地适配 × 回退方案”的简短对比。
直接复用本技能的已验证蓝图时，把精力放在业务叙事和真实数据上，不重复形式化调研。

### 1.4 阶段 D：实现

按依赖顺序实现：指标元数据 → PageRegistry → 设计令牌 → 页面骨架 → 组件与图表 → 交互与动效 → 基础降级；有明确打印/PDF需求时再补打印适配。
避免先写完静态页面，再在最后补导航状态、移动布局和 reduced-motion；这些属于架构，不是收尾装饰。

### 1.5 阶段 E：验收与交付

验收按 §9 执行。任何视觉升级都要同时提交：当前成品、关键状态截图、浏览器断言、数据复算、交付面哈希。
“代码看起来正确”“浏览器能打开”“某张旧截图很漂亮”都不能独立作为交付依据。

## 2. 体验定位与信息架构

### 2.1 四种体验模式

| 模式 | 主要目标 | 首页结构 | 导航与动效 | 密度建议 |
|---|---|---|---|---|
| Executive Brief | 快速判断与决策 | 结论标题 + 主 KPI + 主证据 + 风险/行动 | 引导式分页、进度、短过渡；可切换自由导航 | 3–5 个主要视觉/页 |
| Operational | 监控与处置 | 状态带 + 告警 + 趋势 + 责任清单 | 筛选优先、即时反馈、少装饰动画 | 5–8 个视觉/页，按例外排序 |
| Analytical | 探索与解释 | 多维筛选 + 主图 + 联动明细 | 下钻、刷选、联动、可回溯路径 | 可较高，但需渐进披露 |
| Learning | 理解与培训 | 章节目标 + 解释 + 示例 + 练习 | 侧栏章节目录、步骤进度、讲义可复习 | 内容型，不硬套 KPI 首页 |

密度数值是评审触发线，不是机械配额。若一页超过 6 个主要视觉，先检查是否混入了第二个问题，而不是直接拆页。

### 2.2 高管汇报的三层叙事

1. **判断层**：本期结论、最重要数字、好坏与风险。5 秒内可读。
2. **证据层**：趋势、对比、结构、异常贡献。30 秒内能解释“为什么”。
3. **行动层**：责任、优先级、下一步与下钻入口。让观众知道“然后做什么”。

推荐页面骨架：结论标题 → 决策摘要带 → 主证据区 → 次要证据/异常 → 行动或导航。
不要把最重要的结论埋在页脚注释或 tooltip 里。

### 2.3 每页一个视觉锚点

视觉锚点可以是主数字、主趋势、异常矩阵或行动路径，但必须只有一个第一优先级。
其余元素通过尺寸、位置、明度、边框与留白退后，而不是都加渐变、阴影和彩色顶条。

采用三级组件层级：

- L1 Hero：每页最多一个，大数字或主图，拥有最大面积与最高对比。
- L2 Evidence：2–4 个，为主结论提供证据。
- L3 Context：口径、来源、辅助指标、说明；可读但不争抢注意力。

### 2.4 演示模式与探索模式

领导层汇报常需要两种路径：

- **演示路径**：上一页/下一页、进度、关键结论按 2–4 组出现、可用键盘直接定位。
- **探索路径**：全局导航、筛选、下钻、明细与返回路径。

二者共享同一份数据和 PageRegistry，不复制两套页面。默认让观众可以直接跳转，不强制线性看完。
快捷键在输入控件内必须停用，并始终提供可见按钮作为等价入口。

### 2.5 两族页面：演示型与长读型（**先分族，再定参数**）

本手册默认面向**演示型**（高管汇报、现场讲解、大屏投影）。另有一族同样常见、但判据相反的页面——**长读型**：

| | 演示型（本手册默认） | 长读型（指导手册 / 白皮书 / 培训材料 / 文件型长文） |
|---|---|---|
| 读者状态 | 站着听，30 秒抓结论 | 坐着读，可滚可停可回看 |
| 页面组织 | 分页切页，每页一个结论 | 连续长文，章节锚点导航 |
| 信息密度 | 低，主动做减法 | 高，允许成段文字 |
| 成功判据 | 讲得完、看得懂 | 查得到、读得下去 |

**长读型的载体默认是桌面，不是手机**（P3 主题默认值，按实际受众可调）：

| 项 | 默认值 | 说明 |
|---|---|---|
| 版心 | 1320px | 超过 1400 行长过宽，阅读疲劳 |
| 正文字号 | 17.5px | 16px 在 1440 下发虚 |
| 图表宽度 | 1120px | 与正文对齐，不做满宽出血 |
| 移动端 | **只做兜底** | 无横向溢出、表格不裁列、导航可开合即可 |

> **判据一句话：不要因为“手机能打开”就按手机 H5 做。** 长读型页面的主场景是坐在电脑前读，按 390px 设计会让桌面端变成一条窄柱。
> 这条与演示型的“390px 必测”不冲突：**必测 ≠ 按它设计**（见 §8.1）。

配色方法与视觉语言仍可复用 `references/executive-visual-system.md`，但**不要直接把演示型的深色大卡、彩色顶条搬到长读页**——长读页的层级靠排版节奏与留白建立，不靠卡片堆叠。

## 3. 视觉设计系统

详细参数、主题配方和组件反模式见 `references/executive-visual-system.md`；可复制令牌见 `assets/executive-h5-kit/tokens.css`。
本节只固定跨主题有效的设计逻辑。

### 3.1 深浅表面：先审必要性，再修边缘

浅色页面默认用同主题浅色表面建立层级。深色大卡只用于少量“高对比时刻”，不能成为高管汇报的默认模板。
完整判据与代码见 `references/executive-visual-system.md` §3；可复制变量见 `tokens.css` 的 `hero-*` 与 `.h5-card--hero-light`。

边缘处理除「内高光 + 过渡边 + 柔光」的三层硬边外，还有一条备选：**羽化（柔化边缘）** —— 让卡片 alpha 在边缘一圈内渐变到背景。它直接削弱明度差本身，适合深色/彩色大卡压浅底仍显“贴上去”的情形；代价是**与投影互斥**（`mask` 会裁掉 `box-shadow`）、**打印需关羽化**。半径按卡片尺寸与明暗差实测，没有通用值。判据与代码见 `references/executive-visual-system.md` §3.4.1 —— 属可选手法，不是默认规范。

**深色 Hero 的三次审查：**

1. **必要性**：是否只有一个核心判断需要强调？改成浅色后是否真的会损失焦点？长文、培训、密集表格、连续多页默认不用深色大卡。
2. **色彩关系**：冷灰底优先低饱和蓝青/石板蓝，暖纸底优先暖石墨/深棕灰；默认避免纯黑和无依据的冷暖拼贴。深色内部只用同色系小明度变化。
3. **边缘与内部资产**：边缘由内部同色层次、约 1px 渐变过渡边、同色柔光与轻内高光共同完成；卡内文字、图标、图表与图片也要按局部深色主题适配。

深色面积超过首屏约三分之一时，只触发一次必要性复审，不作为机械合格线。普通卡片需要与背景分开时，优先 surface、间距和细边，不动用深色。

**浅底浅卡的内容突出顺序：**

位置与跨度 → 字号字重与留白 → 同温表面层级 → 细边和按需阴影 → 小面积品牌/状态强调。
普通卡片不应全靠阴影浮起，也不能为了柔和而牺牲文字、单位和来源的可读性。浅色页面可使用 `.h5-card--hero-light`，不靠反色也能建立第一焦点。

### 3.2 先建立角色令牌，再写组件

颜色至少分五组，不能用“主色不超过 3 个”混淆所有角色：

1. 表面色：页面、卡片、浮层、分区。
2. 文字色：主文、次文、弱文、反色文字；弱文仍须满足可读性。
3. 品牌色：身份、关键动作、当前选中。
4. 数据色：当期、参照、类别、顺序、发散。
5. 状态色：正向、负向、告警、未知；另有市场涨跌语义时单独命名。

“数据色只表达数据语义”不等于“全站颜色不能有装饰作用”。氛围与品牌可以存在，但不能改变数据判断。
中国金融行情默认涨红跌绿；一般经营状态可使用绿=正向、红=风险。两套语义不得靠同一个 `red/green` 变量猜测。

### 3.3 配色按数据关系选择

- 离散类别：使用分类色板；类别超过可辨数量时，优先直接标注、合并小类或改图型，不无限加色。
- 单向数值：使用顺序色板；浅底主题通常深色表示更大，深底主题通常更亮表示更大。
- 围绕有意义中点的正负偏差：使用发散色板，中点必须是 0、预算或明确基准，不可随意取中位数。
- 当期与参照：当期用品牌/强调色，参照用中性灰；不要让参照比当期更鲜艳。
- 状态与类别分离：红色若表示风险，就不要同时把红色当成普通第三类。

渐变可用于氛围或小面积材质，但不能代替有数据含义的顺序/发散色板。多重渐变、每卡不同渐变和彩色光晕会削弱数据层级。

### 3.4 对比度按“令牌 × 字号 × 实际底色”验收

普通文本最低 4.5:1；大文本最低 3:1。大文本门槛按 WCAG 定义判断，不能把所有 18px 字都当作大文本。
非文本控件与关键图形还需检查 3:1 的可辨识性。口径、单位、来源不是装饰文字，不允许用 2.x:1 的浅灰淡化到不可读。

自动计算后仍需截图目视，因为透明叠层、渐变、打印和实际字体都会改变结果。

### 3.5 字体与数字

- 中文汇报可使用“有展示感的标题字 + 克制正文字”；分析型看板可统一无衬线，通过字重和尺寸建立层级。
- 远程字体必须可回退；离线单文件优先本机字体栈或合法内嵌子集，不能因字体加载失败失去排版。
- 数字使用 `font-variant-numeric: tabular-nums`，避免刷新和滚动时横向跳动。
- 大数字、标签、单位、比较语境构成一个整体；单位不可为了压行而消失。
- 不用字体大小 alone 表示所有层级，同时利用留白、位置和字重。

### 3.6 布局不是均分卡片

使用栅格保证对齐，但允许主证据占更大跨度。推荐 12 列骨架：

- L1 主证据：7–8 列；侧旁异常/判断：4–5 列。
- 次级证据：按问题需要 4/4/4 或 6/6，不机械所有区域三等分。
- 上下文信息：用细分隔、底栏或文本块，不必全部装进卡片。

卡片圆角、边框、阴影和玻璃都属于主题。社论纸本可以使用 1px 规则线，墨夜指挥可以使用细亮边，瓷白主题可以使用柔和浮层。
禁止的是无差别叠加，不是某一种材质本身。

### 3.7 记忆点与“惊艳”的判据

一个有效记忆点应能被观众复述，例如“首页那个把成本偏差直接连成行动清单的主图”。
以下不构成稳定记忆点：所有卡片都浮动、蓝紫渐变背景、无限呼吸灯、每张图都重新生长、无信息含义的粒子与光效。

高质量感通常来自：精准对齐、明确的明暗层级、合适的字体、一个独特构图、及时且一致的反馈。
动效只能放大这些基础，不能替代它们。

## 4. 导航、窗格与分片切页

完整状态机与代码见 `references/navigation-motion-charts.md` 和 `assets/executive-h5-kit/shell.js`。

### 4.1 按任务选择导航，不堆叠导航

| 内容形态 | 首选全局导航 | 局部导航 | 不建议 |
|---|---|---|---|
| 3–5 个同级页面 | 顶部 Tabs 或演示步进 | 页内锚点按需 | 同时再加侧栏和右侧 dock |
| 6–12 个章节/课程 | 侧栏或移动抽屉 | 当前页目录 | 顶栏挤两行页签 |
| 长文单页 | 顶部章节条或侧栏，二选一 | 滚动 spy / 本页目录 | 三处重复导航长期共存 |
| 引导式高管汇报 | 上一页/下一页 + 进度 + 可直接定位 | 当前页少量锚点 | 强迫线性播放 |
| 分析探索 | 筛选 + Tabs | 面包屑/下钻返回 | 把筛选状态藏进导航 |

同一时刻最多保留一个全局导航和一个当前页局部导航。响应式切换可以改变形态，但由同一 PageRegistry 生成。

### 4.2 PageRegistry 是导航与页面的单一事实来源

每个页面登记：`id`、导航名、标题、结论、章节、是否可见、图表清单、滚动策略和打印策略。
导航名称、H1、元信息若业务上要求一致，就由同一字段派生或有构建断言，不能手工维护三份。

筛选、当前页、下钻路径、浮层是四种不同状态，不应混成一个全局布尔集合。
推荐状态：`route`、`filters`、`drillPath`、`overlay`。`hideSection` 只表达筛选结果，最终可见性由一个 render/select 函数统一裁决。

### 4.3 页签必须具备完整行为

顶部/侧栏页签若采用 ARIA Tabs，应具备：

- `tablist` 有可访问名称；`tab` 的 `aria-controls` 指向 `tabpanel`。
- 选中项 `aria-selected=true`，其他为 false；`tabpanel` 用 `aria-labelledby` 回指页签。
- 只有一个页签在正常 Tab 顺序中，方向键移动，Home/End 可选；垂直页签使用上下键。
- 页面预载且切换无明显延迟时可自动激活；重计算页面采用手动激活，避免方向键经过时连续等待。

普通章节链接不需要伪装成 `role=menu`。使用不完整的 menu 角色比使用原生链接更差。

### 4.4 窗格分四类

| 窗格 | 用途 | 交互要求 |
|---|---|---|
| 导航窗格 | 章节与页面定位 | 当前项、折叠状态、移动抽屉、焦点返回 |
| 筛选窗格 | 高频或高级筛选 | 已选条件可见、重置、结果数量、状态唯一 |
| 详情窗格 | 查看单个主体/指标详情 | 不丢失当前页；桌面侧栏，移动近全宽；Escape 关闭 |
| 工具窗格 | 导出、说明、演示控制 | 不遮挡主结论；避免多层弹窗叠加 |

频繁比较的信息不要放进只能一次打开一个的 modal；使用并列区域或非模态侧栏。
模态抽屉需要焦点约束、背景不可交互、Escape 和返回触发按钮；非模态抽屉不要误用 modal 行为。

### 4.5 切页的正确顺序

1. 接收输入并计算最新 route，旧异步结果用序列号作废。
2. 更新页签状态与面板可见性；核心内容不等待动画。
3. 首次显示的图表在容器有真实尺寸后 init；已有实例按需 resize。
4. 更新焦点、滚动与 URL；不把所有切页都强制送回页面顶部。
5. 在支持且未减少动效时执行短过渡；不支持时直接呈现最终态。

默认使用 `hidden` 或统一的页面类控制可见性，不让多个函数分别写 `style.display`。
View Transition API 是渐进增强，不是依赖；无该 API 时必须同样完整可用。

## 5. 动态图表与动效

### 5.1 把动效分为五种语义

| 类型 | 要解释什么 | 推荐做法 |
|---|---|---|
| 首次进入 | 信息组织的先后顺序 | 2–4 组错峰，主结论先出；只播放一次 |
| 数据更新 | 哪些值增加、减少、移入或移出 | `setOption` diff + `animationDurationUpdate`，保持稳定 name/id |
| 下钻/聚合 | 总体与组成部分的关系 | 稳定 id/groupId 时用 universal transition；否则短更新 |
| 页面转换 | 信息层级与空间位置如何变化 | 短淡变/位移或 View Transition；不清空所有图重播 |
| 状态反馈 | 选中、悬停、加载、成功、错误 | 100–200ms 反馈，立即提交状态，不排队 |

“图表动起来”不是目标。静态报告、频繁筛选和实时刷新都可以选择更弱或完全关闭动画。

### 5.2 切页重播只是可选演示模式

ECharts 的默认优势是数据更新过渡，而不是每次切页 `clear()`。
只有用户明确要求“每次进入页面重播”或提供显式重播按钮时，才启用 replay 模式，并满足：

- 保留最终配置的可靠副本，不能假设 `getOption()` 永远保留所有自定义对象。
- `clear()` 后 `setOption` 失败必须恢复图表并记录错误，不得留下空白。
- 不阻塞下一页操作；最新切页优先，旧任务取消。
- 若必须设锁，时长由实际最大 `delay + duration` 计算，不能注释写 1.2s、代码锁 1.4s、实际却 1.7s。
- 解锁与清理由独立定时器或 Promise 完成，不只放在可能节流的 rAF 内。

### 5.3 动效要可中断、可重定向

连续点击筛选或页签时，旧动画和旧异步结果不得覆盖最新状态。优先使用序列号/AbortController/取消旧 WAAPI 动画，而不是全局长时间禁用输入。
业务状态立即更新，动画只表现当前状态到最新状态的变化。

推荐时间预算（P2 起始值，不是强制标准）：状态反馈 100–180ms；数据更新 220–360ms；窗格 180–300ms；页面 280–450ms；首次主场景 450–700ms。
空间运动与透明/颜色反馈使用不同节奏；透明和颜色不需要明显回弹。

### 5.4 reduced-motion 是完整输入，不是 CSS 补丁

必须同时覆盖：

- CSS keyframes、transition、无限 pulse 和滚动 reveal。
- ECharts 首次 `animationDuration`、更新 `animationDurationUpdate` 和显式 replay。
- 数字 count-up、SVG/Canvas 自写动画和程序化平滑滚动。
- View Transition 或其他页面过渡。

用 `matchMedia('(prefers-reduced-motion: reduce)')` 读取并监听运行时变化。减少动效后直接给最终值/最终位置，内容不消失。
ECharts 可设置 `animation:false` 或将相应时长设为 0；仅证明 `clear()` 次数为 0，不等于证明没有首次动画。

### 5.5 数字与图表的可信动效

- 数字滚动只用于低频、关键值；结束时必须落到精确格式化结果，不能停在四舍五入中间值。
- 屏幕阅读器直接获得最终值，不逐帧播报；不用 aria-live 播放动画过程。
- 图表截图等待 `rendered` 或关闭动画后获取，不能 `setOption` 后立即把起始帧当最终态。
- 数据量大时关闭动画或调整 `animationThreshold`；性能优先于“每张图都动”。
## 6. 图表与数据表达

### 6.1 从问题选图，不从效果选图

| 要回答的问题 | 首选 | 关键约束 |
|---|---|---|
| 谁高谁低、异常在哪 | 排序条形/柱状 | 比较类排序；长名称横向；柱图零基线 |
| 何时开始变化 | 折线/面积 | 默认 1–3 条主线；转折点直接标注 |
| 与预算/目标差多少 | 子弹图、偏差条、目标刻度 | 明确基准与单位，比仪表盘更节省空间 |
| 构成如何 | 堆叠条、少量类别的环图 | 精确比较优先条形；类别多时不靠无限色板 |
| 总体由谁贡献 | 瀑布、贡献排序、分解 | 区分绝对贡献与比率 |
| 分布和相关 | 散点/箱线/直方图 | 对数轴必须明确标记并解释原因 |
| 核账与取数 | 表格 | 排序、筛选、导出、单位与空值完整 |

3D、旋转饼、无意义仪表盘和装饰性面积会扭曲比例或降低比较效率，不作为高管看板的“高级效果”。

### 6.2 图表层级与主题注入

所有图共享一个主题层：文字、轴线、网格、提示框、状态色、动画与响应式默认值统一注入。
单图只声明业务编码、数据、单位与必要标注。禁止逐图复制一套样式后手工微调，造成同类图视觉不一致。

默认弱化轴线和网格，让数据与直接标注成为前景。柱体、折线和面积不要求统一渐变；实心色往往更清晰。
参考线与数据标签冲突时，优先移动标签或降低参考线权重，不用文字描边掩盖碰撞。

### 6.3 口径、来源和快照是数据编码的一部分

每个数据集/系列至少能追溯到：指标、公式、单位、期间、来源、快照、口径类型。
官方自报、独立测评、不同测试环境或不同期间的数据，不因单位相同就可以直接混排。
若确需同页展示，采用分面、分组或明确分区，禁止用星号脚注替代结构性区分。

关键图旁提供人类可读的一句话结论和必要的数据表/明细等价物。ECharts `aria.show` 可增强读屏描述，但不能替代编辑过的结论与来源。

### 6.4 指标卡与数字规则

KPI 的完整结构：标签、主值、单位、比较基准、变化、期间；sparkline 只在其能补充趋势时加入。
“没有对比语境的大数字”通常只是装饰，但健康度、计数等确有自明语境的指标不必强行加同比。

| 项目 | 规则 |
|---|---|
| 空值与 0 | 未知/缺失用 `—`；真实 0 必须显示 0，二者不可互换 |
| 精度 | 计算保留全精度，展示最后统一舍入；同页同口径同精度 |
| 单位 | 万元/亿元、%、pp、人等明确；差额与增长率不混用 |
| 倍数 | “是 N 倍”与“增加 N 倍”使用不同公式和文案模板 |
| 比率 | 花钱的实际÷预算称预算使用率；赚钱的实际÷目标才称达成率，按业务定义登记 |
| 计数 | KPI、图表合计、表格行数和中心文字同源，至少有跨视图等式断言 |

### 6.5 三类时间不可混用

- 数据截至：只来自数据元信息。
- 成品生成：来自构建过程。
- 页面打开：来自浏览器墙钟，只能明确标成“浏览日期”。

禁止用 `new Date()` 刷新“数据截至”或让旧档案在打开时伪装成新数据。期间、月份和“最新”文案从元数据派生。

### 6.6 图表工程的五个高频陷阱（P1，均为实测翻车点）

**① 浅合并会吞掉嵌套配置。**
`Object.assign({自定义 axisLabel}, AX)` 会被 `AX.axisLabel` **整体覆盖**，单图写的 `formatter`、颜色全部丢失，且不报错。
凡“默认样式 + 单图定制”的组合，一律用深合并（**自定义优先，默认只补缺**）：

```javascript
function mergeObj(target, src) {           // 递归浅层覆盖，src 补缺
  for (var k in src) {
    if (src[k] && typeof src[k] === 'object' && !Array.isArray(src[k])) {
      target[k] = mergeObj(target[k] || {}, src[k]);
    } else if (!(k in target)) { target[k] = src[k]; }
  }
  return target;
}
function mergeAxis(o) { var b = {}; mergeObj(b, AX); mergeObj(b, o); return b; }
// 用法：xAxis: mergeAxis({ type:'value', max:5, axisLabel:{ formatter:'{value}%' } })
```

**② 双 grid 双轴图：区间必须物理隔离。**
左 grid 的 `right` 必须小于右 grid 的 `left`（两区不重叠）。否则**视觉混轴**——两系列条形叠在同一区域、刻度交错、标签互相压盖（实测案例：左 `right:10%` 撞右 `left:62%`）。

```javascript
grid: [{ left:'9%',  right:'56%' },
       { left:'63%', right:'7%'  }]   // 63% > 56%，中间留 7% 安全区
```

**③ 状态渲染三件套。**
存量看板最常见的短板是**只有正常态**。三种状态必须在中央 helper 里统一处理，不要各页各写：

```javascript
/* 表格空态：colspan 必须等于列数，否则表格塌成一条 */
tbody.innerHTML = rows.length
  ? rows.map(rowHtml).join('')
  : '<tr><td colspan="9" class="empty-cell">暂无匹配数据，请调整筛选条件</td></tr>';

/* 图表空态：有数据时清空 graphic，无数据时注入居中文案 */
var hasData = false;
(option.series || []).forEach(function (s) { if (s && s.data && s.data.length) hasData = true; });
if ((option.series || []).length) {
  option.graphic = hasData ? [] : [{ type:'text', left:'center', top:'middle', silent:true,
    style:{ text:'暂无数据', fill:'#9AA7B3', fontSize:14 } }];
}

/* 异常态：容器需 position:relative，浮层不撑开布局 */
try { chart.setOption(option); }
catch (e) {
  var d = document.createElement('div');
  d.className = 'chart-error';
  d.textContent = '图表渲染失败：' + ((e && e.message) || '未知错误');
  dom.appendChild(d);
}
```

> 空值显示 `—`、真实 0 显示 `0`——这条在 §6.4 是数据规则，在渲染层同样成立，不要用空态文案吞掉真实的 0。

**④ 不要手写大段内联对象数组字面量。**
`series: [{ data: [ {name:'A',value:1}, … ] }]` 的逗号/括号错配概率随长度上升，且 **SyntaxError 会让整个 `<script>` 块静默挂**——页面不报错、只是什么都不显示。统一用循环构造：

```javascript
var pts = [];
for (var i = 0; i < rows.length; i++) pts.push({ name: rows[i].n, value: rows[i].v });
```

**⑤ 分类轴长标签要预留 `grid.left`。**
标签 ≥6 字时，`grid.left` 至少 90—115px，否则被裁（实测：8 字标签「制作人员（计件）」在 `left:70` 下被裁切）。

## 7. 工程、性能与构建

### 7.1 默认技术栈按约束选择

- 单文件 HTML + 内联 CSS/JS + 内嵌 ECharts，适合离线转发和归档。
- 现代浏览器/WebView 默认使用清晰、可维护的现代 JavaScript；只有明确旧环境基线时才限制到 ES5 或增加转译。
- ECharts 版本必须锁定并记录。不要在视觉改版中顺带跨大版本升级；升级单独做兼容与截图回归。
- 需要登录、数据库、多人协作或文件存储时，选择应用架构和云服务，不塞进离线单文件。

### 7.2 源码、分片与数据

- 成品只由 `build.py` 或等价构建脚本生成；内容改源码分片，数据改数据源/导出器。
- 分片按语义组织，不必机械一个 `partNN` 放一章；文件名和顺序在构建脚本中显式登记。
- 数据字段由声明式指标 schema 驱动：先登记必需字段，再裁剪无用列并校验缺列，避免“只抽看起来要用的列”造成静默缺字段。
- 改数据源后检查后置校正/覆盖函数和缓存，防止旧值回写。
- JS 语法用 `node --check` 或真实解析器，不用括号计数。正则、模板字符串和注释会让朴素计数产生误报。

### 7.3 图表实例与尺寸

- 不在 `display:none` 或零尺寸容器中初始化图表；采用可见后懒初始化或先取得真实尺寸。
- 实例按容器复用；筛选更新用 `setOption`，不要每次重绘都重新 init。
- resize 使用 ResizeObserver/窗口事件节流，并只处理可见且尺寸变化的实例；页面销毁时断开观察与事件。
- 隐藏页不必每帧消耗资源；切回时先获得尺寸再更新或 resize。

### 7.4 性能预算

数据量、图形数量、同时运行动画数和低端设备共同决定性能，不能只看书本阈值。
大数据优先裁剪、聚合、按需加载、progressive/SVG/Canvas 合理选型；超过动画阈值时关闭动画。
骨架屏在快速本地加载时可能造成闪烁，只有真实等待存在且超过可感知阈值时使用。

## 8. 响应式、可访问性与降级

### 8.1 移动端要重组，不是缩小整张看板

390px 验收不只看 `scrollWidth`。还要检查：正文字号、图表有效绘图区、轴标签碰撞、触控目标、抽屉焦点和表格可读性。
长标签横条图、双轴图和密集矩阵可提供独立移动 option、简化标签或改为列表/卡片。
禁止用整体 `scale()` 把桌面看板缩小到“没有溢出但看不清”。

### 8.2 可访问性最低集合

- 使用 header/nav/main/section/footer 与正确标题层级；唯一主标题。
- 所有功能键盘可达；`:focus-visible` 清楚；触控目标建议至少 44×44px。
- 页签、抽屉、当前导航项的状态与视觉同步；不以 ARIA 属性代替真实键盘行为。
- 图表有可访问名称、编辑过的摘要与必要数据等价物；颜色之外用文字、形状、线型或贴花编码。
- 覆盖默认、悬停、按下、焦点、禁用、加载、空、错误等适用状态。

### 8.3 无 JS 与异常降级

核心内容默认在 HTML 中可见，增强脚本只负责交互。若业务必须依赖 JS，提供明确 noscript 说明和可读的核心摘要，而不是空白页。

### 8.4 打印与 PDF 是条件任务，不是默认验收

H5 默认只保留低成本的基础打印降级：内容最终态可见、关闭动画、恢复纯色文字、隐藏导航和交互控件，并保留数据来源与期间。做到这些即可，不要求真实打印机、打印预览或 PDF 截图成为每次交付的必需项。

只有用户明确提出打印/PDF交付时，才增加相应验收：可选择另存 PDF 检查视觉效果，但不以拥有真实打印机为前提。
需要正式打印、复杂分页、页眉页脚、签字或归档排版时，优先制作 Word，而不是在 H5 中模拟纸张。H5 的主交付形态仍是网页与界面。

## 9. 验收与交付

### 9.1 七重验收

| 验收 | 必须证明 | 不能替代什么 |
|---|---|---|
| 静态与语法 | ID/锚点/ARIA 关联、CSS 变量、JS 解析、资源完整 | 不能证明浏览器布局与视觉 |
| 数据独立重算 | 关键数、跨视图等式、全精度与期间口径 | 不能证明图表映射无误，需结合文字/截图 |
| 浏览器交互 | Tabs、筛选、抽屉、键盘、深链、焦点、异常与最新输入优先 | 不能证明观感 |
| 视觉截图 | 当前成品、整页、关键局部、不同页签/主题/状态 | 不能证明数据正确 |
| 响应式 | 桌面常见宽度 + 390px；有效绘图区与可读性，不只零溢出 | 不能只靠设备模拟代替真实触控抽查 |
| 降级与可选打印 | reduced-motion、无 JS/异常、基础打印规则；仅声明打印/PDF交付时验证对应产物 | 不能只检查 CSS 而漏掉 JS/ECharts；不把真实打印当默认前提 |
| 交付一致性 | 所有工作/最新/分发/快照的哈希、版本、数据期间 | 不能只比较项目内两份副本 |

### 9.2 截图可信化与 manifest

截图前确认是最终态：可等待字体、图表 `rendered` 和动画完成；审计副本可注入终态覆盖，但不得把覆盖样式误写进交付物。
整页截图用于构图，单卡原像素/放大截图用于标签与边缘，两者不可互相替代。

manifest 至少记录：成品 SHA256、截图时间、页签/路由、视口、主题、动效偏好、是否注入终态、文件名。
旧截图即使内容相近，也不能自动算作当前版本验收证据。

### 9.3 视觉评审的固定镜头

每次全局视觉升级至少看：

1. 首屏全景：是否有唯一焦点和明确结论。
2. 每个页签：是否出现风格断裂、空图和密度失控。
3. 主图单卡：标签、参考线、tooltip、图例、空态。
4. 导航与抽屉：默认、选中、焦点、移动开合。
5. reduced-motion：内容是否仍为最终态；有明确打印/PDF需求时，再检查对应打印/PDF画面。

### 9.4 交付门禁

列出所有交付面，而非只写“工作版=副本”。哈希不一致、数据期间不一致或“最新”指向旧版时，停止发布并先修复。
发布上线另走发布技能；本技能负责保证待发布产物本身一致、可验收。
## 10. 故障速查

先按症状定位，不直接套历史修复参数。完整案例证据见 `references/case-patterns.md`。

### 10.1 视觉与布局

| 症状 | 优先检查 | 处理方向 |
|---|---|---|
| 页面像均质卡片海、没有重点 | 是否所有卡同尺寸/阴影/色条；标题是否只有主题 | 重建 L1/L2/L3，主证据扩大，结论前置 |
| 单元素参数都对，拼起来难看 | 背景、表面、文字是否同温；强调色是否过多 | 回到令牌与整页截图，不继续逐卡加效果 |
| 白卡与浅底糊在一起 | 实际叠加后的明度、边框/阴影层级 | 调整表面层级；可用细边或阴影，不限定玻璃方案 |
| 渐变/纹理盖住内容 | pseudo element 层叠、mask、backdrop-filter | 先降级为背景层，再逐项恢复；不要凭参数猜 |
| 移动无溢出但看不清 | 是否整体 scale；绘图区被轴标签/边距挤没 | 重排与移动 option，禁止只藏溢出 |

### 10.2 图表与动效

| 症状 | 优先检查 | 处理方向 |
|---|---|---|
| 图表空白或 0×0 | 隐藏容器 init、JS 首错、clear 后 setOption 失败 | 可见后 init；恢复配置；记录错误，不静默吞 |
| 切页闪白 | CSS 动画是否被 display 取消；是否同时 clear + 卡片淡入 | 内容默认终态；页面与图表只保留一种主运动 |
| 数据更新不动 | 是否仍 clear 重播、name/id 不稳定、时长被覆盖 | 使用 setOption diff 与 update 动画，稳定数据身份 |
| 动画有时失效 | 锁是否在 rAF 内释放、固定锁时长是否过短 | 最新任务优先；清理独立注册；按实际预算计算 |
| 减少动效仍有动画 | ECharts 首次、数字、smooth scroll、无限 CSS | 全面读取 motion preference，不只关 reveal |
| 截图发灰/空白 | 是否捕获起始帧或 reveal 非终态 | rendered/终态覆盖后重拍，先排除截图假象 |
| 标签与参考线相撞 | 标签位置、网格边距、z 层与直接标注 | 移动标签/降权重/改图型，以局部放大截图裁决 |

### 10.3 数据与交付

| 症状 | 优先检查 | 处理方向 |
|---|---|---|
| 数与源表不一致 | sheet/列映射、期间、后置覆盖、舍入路径 | 重建映射并独立重算；全精度计算后统一舍入 |
| KPI、图、表计数不同 | 是否分别硬编码 | 同源派生或加入跨视图等式断言 |
| 导航名与 H1 不同 | PageRegistry 是否只生成了导航 | 统一命名契约并断言 |
| 旧页面月份变新 | 是否用墙钟驱动数据期间 | 数据截至只取元数据 |
| “最新”实际是旧版 | 是否只校验项目内副本 | 全交付面清单与哈希门禁 |

## 11. 反模式与经验边界

### 11.1 设计反模式

1. 把“高级”理解为更多渐变、玻璃、阴影、粒子和动画。
2. 所有页面使用相同 KPI 卡阵列，没有主证据与结论标题。
3. 每页同时存在多个第一视觉焦点，或每张小卡都有彩色顶条。
4. 把主题默认值当正确性规则，例如禁用所有 1px 边框或所有整页渐变。
5. 为了“手机适配”整体缩小桌面画布，或只用 `overflow-x:hidden` 掩盖问题。
6. 浅色页面默认套深色大卡，未审必要性、色温与面积；暖纸底直接搭冷蓝灰深卡。
7. 深色卡只用透明边框和一块重阴影，没有渐变边缘、同色柔光及卡内资产的局部主题适配；或浅底浅卡全靠阴影分层。

### 11.2 交互反模式

1. 同时维护顶部、侧栏、dock 三套导航，却没有统一 registry 和当前状态。
2. ARIA 只加角色，不做方向键、焦点和状态同步。
3. 切页时先清空图表，再让卡片和图表同时从透明状态进入。
4. 用长全局锁阻止输入，或让旧动画/旧异步结果覆盖最新筛选。
5. reduced-motion 只处理 CSS reveal，遗漏 ECharts、数字与平滑滚动。

### 11.3 数据与工程反模式

1. 不同来源/测试口径的数据共用排行榜，再用星号免责。
2. 先舍入美元，再换算人民币；或把“涨至 3.3 倍”写成“多花 3.3 倍”。
3. KPI、中心文字、图表和表格分别硬编码同一计数。
4. 成品、最新副本和快照各自修改，哈希检查只覆盖其中两份。
5. 静态审计用括号平衡代替 JS 解析，或把项目专属死函数写成全库通用规则。
6. 没有打印/PDF交付需求仍强制真实打印验证；需要复杂分页与正式归档时仍硬做 H5 打印，而不转 Word。

### 11.4 不应泛化的历史经验

- 特定玻璃边缘参数、20px 圆角、14px 卡片间距：仅为主题配方。
- 每次切页必须重播图表：仅为明确演示需求。
- 某页固定六列、某图固定柱宽、某组织树竖排：仅为局部布局。
- 特定项目的权限分包、主体配色、页面名称与章节数量：仅为业务配置。
- 某个历史 bug 的具体类名和函数名：留在案例，不进入通用静态审计判据。
