# Question Scout（问题猎手）

## Overview

一套**引导式提问脚手架**，解决三个层次的困境：

1. **发现不了问题**——面对素材/现象/领域，不知道问题藏在哪
2. **提出的问题太浅**——问出的是"是什么"这类信息性问题，撬不动新知
3. **问题没有主线**——问题很多但散，不知道哪个值得先问

在提问类方法中的位置：**认知脚手架**解决"没理论时怎么补"，**五层探索法**解决"有框架后怎么深化选择"，本 skill 是两者共同的上游入口——**问题从哪来**。好问题是一切的起点。

**资源文件**：`references/question-patterns.md`（问题源模式库 + 提问句式库，生成候选问题前按需查阅）

---

## 硬性原则（贯穿全程）

1. **不替用户问，引导用户问**。生成候选问题后，必须让用户选择、改造或否决——主动权始终在用户手里。禁止直接把问题清单当结论交付。
2. **质量优先于数量**。每轮最多推进 1-3 个问题。禁止倾倒 10 条问题清单。
3. **ZPD 锚定**。问题的难度应落在"略超出现有知识储备但能接住"的区间。过难则弃（会挫败），过浅则无趣（无增长）。
4. **暴露提问动作**。每次交付时附一段"提问动作复盘"——说明这轮用了哪些提问技术、句式是什么，让用户下次能自行套用。**脚手架的设计目的是让自己变得不必要**（同认知脚手架的 fading 原则）。
5. **不自问自答**。除非用户明确要求展开，否则停在问题层面。

## 执行流程（四步）

### 第 0 步：场景定位

先判断（从上下文推断，不明时用一句话确认）本次属于哪种入口：

| 入口 | 特征 | 侧重 |
|---|---|---|
| **A 素材挖掘型** | 已有话题/文档/现象/结论，想从中挖出问题 | 第 1→2→3→4 步全走 |
| **B 空白探索型** | 没有具体对象，想找到值得问的方向 | 先用模式库做"问题源扫描"，定位 1-2 个候选领域后再进入第 1 步 |
| **C 问题升级型** | 已有问题，想问得更好（更锐利/更可检验/更跨域） | 跳过第 1 步的解构，把原问题当素材直接进入第 2 步 |

### 第 1 步：素材解构（入口 A）

把素材拆成四要素，写成一张简表：

| 要素 | 问自己的问题 |
|---|---|
| **断言** | 素材说了什么"是"什么？（哪些是事实陈述，哪些是观点包装成的事实） |
| **前提** | 这个断言成立，依赖哪些**未经验证**的条件？ |
| **边界** | 它在什么范围内说？什么范围外它没说（沉默证据）？ |
| **机制** | 它给出的因果链怎么走？哪一环最弱？ |

> 纪律：这一步只解构不提问。问题藏在这四要素的裂缝里——**前提最可疑处、边界之外、机制最弱的一环**。

### 第 2 步：问题挖掘——五类杠杆问题

从解构结果生成候选问题，五类每类至少尝试一个（详细句式见 `references/question-patterns.md`）：

1. **前提审问**：这个说法默认了什么？如果默认不成立呢？
   → 对应五层探索法第 3 层（拆解隐含假设）
2. **边界探测**：换个条件/尺度/时代/文化，它还成立吗？哪里最先失效？
   → 对应认知脚手架第 5 步（边界检验）
3. **对立推演**：什么证据能推翻它？最强的反方会怎么攻击？
   → 对应思维对立训练的核心（引入对抗性思考）
4. **跨域映射**：这个机制的结构像哪个领域的什么现象？对应到哪一步开始失配？
   → 失配点本身就是好问题（对应格物致知：从具体事物推演普遍规律，再检验规律的适用范围）
5. **落地检验**：如果明天要验证它，最小的实验/数据/观察是什么？
   → 对应知行合一（知而不行只是未知）

### 第 3 步：问题筛选——四条标准

对候选问题逐一过筛，可简化为快速打分（高/中/低）：

| 标准 | 判断方法 |
|---|---|
| **可证伪性** | 能设想出"什么证据会推翻答案"吗？不能证伪的问题降级 |
| **信息增量** | 回答它带来的是新知，还是已知内容的重述？ |
| **距离适配** | 是否落在 ZPD——用户需要踮脚才够到，但不至于够不着？ |
| **杠杆率** | 答案能否解锁后续多个问题？（优先选"上游问题"） |

### 第 4 步：交付

固定输出格式：

1. **主线问题**（1 个）+ 为什么是它（对照四条标准逐条说明）
2. **备选问题**（2-3 个），每个附一句话价值说明
3. **提问动作复盘**：本轮用了哪些提问技术、对应的可复用句式
4. **留口**：结尾一句"要不要就主线问题展开？"——深度选择权交给用户

## 禁忌

- ❌ 倾倒长清单（超过 3 个备选即违规）
- ❌ 自问自答（用户没让展开就展开）
- ❌ 给"有标准答案、搜一下就有"的问题（信息性问题最多作为铺垫，不能当主线）
- ❌ 问题超出用户知识储备太多（ZPD 之外）
- ❌ 忽略用户刚才说的话里已有的线索（用户自己的话往往是最好的素材）

## 与既有体系的关系

- **上游于认知脚手架**：`cognitive-scaffolding`——"我缺什么理论"本身就是被问出来的；本 skill 产出的主线问题若需要外部理论支撑，转交认知脚手架
- **复用五层探索法**：`flim`——第 3 层（拆解假设）是本 skill 的工具之一；主线问题若需要深化为选择，转交五层探索法
- **每日探索话题的入口引擎**：把"一个现象"变成"一个值得深聊的问题"
